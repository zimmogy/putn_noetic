# PUTN O→B 地图预热修改回顾与精简建议

日期：2026-08-17

## 1. 文档目的

本文档回顾近期为解决以下问题所做的修改，并根据最新一次机器人成功完成 O→B 地图预热的运行结果，判断各项修改的重要性：

- PF-RRT* 起点频繁投影失败；
- 远距离目标受障碍物遮挡和激光雷达量程限制，无法直接规划；
- 已经出现路径但机器人不跟随、偏离路径或长期停滞；
- 恢复动作执行期间已经重新出现路径，但恢复动作没有及时退出；
- `/cmd_vel` 中存在角速度，但 Scout 仿真底盘不能实际转向；
- 自动测试进程与手动/局部控制器可能同时发布 `/cmd_vel`。

本文所说的“重要”主要指对本次 O→B 成功具有直接因果作用；“可撤回”表示不影响 O→B 主流程，或者仅用于调试、统计和后续全地图任务。可撤回不等于必须删除，实际撤回应采用单变量 A/B 测试。

## 3. 当前有效控制链

```text
安全路线检查点
    ↓ 以不超过 2 m 的间距插值
PF-RRT* 局部/滚动路径
    ↓ 路径有效性判断与稳定接管
自动测试路径跟随器
    ↓ 大航向误差时原地转向
/cmd_vel
    ↓ 使用横向半轮距进行左右轮差速换算
Gazebo 轮速控制器和轮胎接触模型
    ↓
Scout 车体产生实际平移和转向
```

只要上述链条中任意一环失效，就可能重新出现“有路径但不走”“有角速度但不转”或“恢复动作覆盖正常路径”的现象。

## 4. 第一优先级：必须保留的核心修改

### 4.1 Scout 底盘获得实际转向能力

涉及文件：

- `putn/src/scout_simulator/scout_description/urdf/scout_v2.gazebo`
- `putn/src/scout_simulator/scout_gazebo_sim/config/scout_v2_control.yaml`

主要修改：

- 轮胎接触参数从 `mu1=10, mu2=10` 调整为 `mu1=2.0, mu2=0.20`；
- `minDepth` 从 `0.01` 调整为 `0.001`；
- 轮速控制器比例增益从 `P=5` 提高到 `P=100`；
- 增加 `gazebo_ros_control/pid_gains`，确保 Gazebo 硬件适配层实际获得轮速 PID；
- 积分限幅从 `100` 提高到 `200`。

重要性判断：最高，必须保留。

修改前，即使发布约 `2 rad/s` 的车体角速度，实测轮速只有约 `0.004–0.014 rad/s`，车体基本不转。修改后，约 4 秒转向测试可以产生约 `84.6°` 的实际偏航。最新 O→B 日志又多次显示路径跟随器发布 `angular.z=±2.0` 后成功完成原地对正。因此，这是从“机器人不执行”到“机器人可以跟随路径”的底层前提。

目前 PID 和摩擦参数是组合验证的，尚不能仅凭一次成功运行精确区分两者的独立贡献。现阶段不应单独撤回其中任意一项。

### 4.2 O→B 人工安全走廊和短程目标插值

涉及文件：

- `putn/src/putn/putn_launch/config/map_test_nav_eval.yaml`
- `putn/src/putn/putn_launch/scripts/run_map_test_nav_eval.py`

O→B 路线检查点为：

```text
O (0.0, 0.0)
→ (-3.8, -2.0)
→ (-7.6, -1.5)
→ (-9.7, 1.5)
→ B (-7.8, 7.8)
```

脚本再按 `interpolation_spacing_m=2.0` 将长线段拆成局部目标。

重要性判断：最高，必须保留。

这项修改直接适配 PF-RRT* 当前的局部地图和滚动扩展方式，避免将被山体遮挡、超出当前激光雷达可观测范围的 B 点直接交给规划器。最新日志明确显示机器人依次通过插值后的预热点 1–11 到达 B 点。

如果撤回插值或直接发布 O→B，起点投影成功也不代表规划器能够一次得到绕山的完整路径，原来的远距离规划失败很可能重新出现。

### 4.3 大航向误差先原地转向，再向前跟随

涉及文件：

- `putn/src/putn/putn_launch/scripts/run_map_test_nav_eval.py`
- `putn/src/putn/putn_launch/launch/map_test_nav_eval.launch`
- `putn/src/putn/putn_launch/launch/map_test_nav_eval_with_sim.launch`

关键行为：

- 航向误差达到 `55°` 时进入原地转向；
- 误差降低至 `20°` 后恢复平移；
- 原地转向最小角速度为 `2.0 rad/s`；
- 移动时角速度限制为 `0.55 rad/s`；
- 当前关闭倒车跟随，斜后方目标先转正再前进；
- 使用进入/退出阈值形成滞回，避免在“转向/前进”之间频繁跳变。

重要性判断：最高，必须保留。

O→B 日志中该逻辑实际触发 8 次。没有这一逻辑，目标位于斜后方时，机器人可能保持前进、沿错误方向运动，或者因为小角速度不足以克服静摩擦而长期停滞。

`2.0 rad/s` 是当前有效值，但不一定是最终最优值。后续可在保持底盘修复的条件下逐步降低到 `1.5、1.2、1.0 rad/s` 做消融测试，不能直接恢复原来的 `0.8 rad/s` 并同时撤回底盘参数。

### 4.4 稳定路径接管和空路径保护

涉及文件：

- `putn/src/putn/putn_launch/scripts/run_map_test_nav_eval.py`

关键修改：

- 单次空路径消息不再立刻清除仍可跟随的有效路径；
- 区分路径消息总数和有效路径消息数；
- 将滚动子路径也视为可用路径，不要求路径终点等于最终目标；
- 检查路径起点与机器人位置是否一致；
- 限制路径切换频率，并根据路径末端、横向偏差和最大保持时间决定是否切换；
- 无进展但已经见过有效路径时，只重新发布目标请求规划，不执行开环前后恢复；
- 正式测试前清除预热阶段遗留的路径状态。

重要性判断：很高，必须保留。

O→B 期间发生 44 次稳定路径接管，说明 PF-RRT* 在持续发布滚动子路径。若脚本每次收到新路径就立即切换，或被一个空消息清空路径，机器人很容易出现来回摆动、偏离路径和停滞。

## 5. 第二优先级：应保留的正确性和安全性修改

### 5.1 使用横向半轮距计算左右轮差速

涉及文件：

- `putn/src/scout_simulator/scout_gazebo_sim/include/scout_gazebo/scout_skid_steer.hpp`
- `putn/src/scout_simulator/scout_gazebo_sim/src/scout_skid_steer.cpp`

官方 PUTN 源码使用纵向轴距 `0.498 m` 参与偏航差速计算。当前修改使用横向半轮距：

```text
0.58306 / 2 = 0.29153 m
```

正确的理想差速关系为：

```text
left  = (v - w × track / 2) / radius
right = (v + w × track / 2) / radius
```

重要性判断：应保留。

它未必是原来“完全不转”的第一原因，因为原公式反而会给出更大的左右轮速度差；但它属于明确的几何修正，决定角速度命令和实际车体响应的比例，撤回后会使后续控制参数难以解释和迁移。

### 5.2 自动测试独占 `/cmd_vel`

涉及文件：

- `putn/src/putn/putn_launch/scripts/run_map_test_nav_eval.py`
- `putn/src/putn/putn_launch/launch/map_test_nav_eval_with_sim.launch`

当前自动测试设置：

```text
launch_local_control=false
require_exclusive_cmd_vel=true
```

重要性判断：应保留。

本次成功运行中没有检测到其他 `/cmd_vel` 发布者，所以独占检查本身没有提高运动性能；但它排除了手动控制器覆盖自动命令这一类隐蔽问题，成本很低，不建议撤回。

### 5.3 启动 bootstrap 及运动有效性检查

当前启动序列：

```text
0.08 m/s, -0.35 rad/s, 3 s
0.00 m/s, +0.35 rad/s, 3 s
```

并要求实际位移不小于 `0.08 m`。本次实测位移为 `0.181 m`。

重要性判断：建议暂时保留。

bootstrap 同时完成三件事：确认底盘能动、让激光雷达看到新的地面区域、避免在地图尚未积累时立即发布第一个 PF-RRT* 目标。它对本次成功可能有帮助，但日志无法证明去掉后一定失败，因此适合后续单独 A/B 测试。

### 5.4 恢复动作发现新路径后立即退出

涉及逻辑：

- `has_new_usable_path()`；
- `execute_cmd_sequence(..., stop_when=...)`；
- `rotate_relative(..., stop_when=...)`；
- `wait_interruptibly()`。

重要性判断：代码应保留。

本次 O→B 没有触发恢复动作，因此它不是本次成功的直接原因；但该逻辑解决了此前“已经出现路径仍继续执行恢复动作”的安全问题。可以关闭恢复功能做实验，不建议删除可中断机制。

### 5.5 使用导航回到测试起点，而不是 Gazebo 瞬移

当前设置 `start_mode=navigate`，避免 Gazebo 瞬移后 A-LOAM 位姿和累积地图不同步。

重要性判断：正式多轮测试应保留；只做一次 O→B 预热时影响较小。

## 6. 尚未证明有效、需要 A/B 测试的修改

### 6.1 激光雷达盲区补丁

涉及文件：

- `putn/src/putn/putn_launch/scripts/patch_lidar_blind_spot.py`
- `putn/src/putn/putn_launch/launch/simulation.launch`

该节点从机器人周围已观测地面估计高度，在车体下方补充一小块点云，目的是提高 PF-RRT* 起点投影成功率。

最新日志在启动初期出现：

```text
Blind-spot patch waiting for TF /camera_init -> base_link
```

之后规划器能够产生路径，说明 TF 或数据流随后可能恢复，但现有 INFO 日志不足以证明盲区补丁在首个有效路径产生前已经实际输出补丁点云。

重要性判断：贡献不确定，不能作为本次 O→B 成功的已证实原因。

建议保留代码，但增加发布计数/补点数量诊断，然后分别运行：

```text
enable_map_blind_spot_patch=true
enable_map_blind_spot_patch=false
```

比较起点投影失败次数和首条有效路径延迟后再决定是否默认启用。

### 6.2 `ratio_min/ratio_max` 从 `0.40/0.85` 改为 `0.02/0.05`

涉及文件：

- `putn/src/putn/putn_planning/config/for_simulation/map1.yaml`
- `putn/src/putn/putn_planning/config/for_simulation/map2.yaml`
- `putn/src/putn/putn_planning/config/for_simulation/map1_wide.yaml`

这些参数会改变点云稀疏度风险的计算，不是单纯的启动或底盘修复。它们可能改变哪些地面被 PF-RRT* 接受，因此属于规划实验变量。

重要性判断：不能根据当前一次成功确定。

建议：

- 恢复 `map1.yaml` 和 `map2.yaml` 的原值，避免无意改变原始 PUTN baseline；当前 O→B 使用 `map1_wide`，撤回这两个文件不会影响该场景。
- `map1_wide.yaml` 暂时保留当前值，并单独进行 `0.40/0.85` 与 `0.02/0.05` 的 A/B 测试。
- 不应把这项参数变化与底盘修复合并成同一个结论，否则后续无法判断成功来自控制还是可通行性阈值放宽/收紧。

## 7. 本次 O→B 未使用，可缩减或撤回的恢复参数

当前投影恢复距离为：

```text
1.0, -1.55, 1.0, -1.95 m
```

并在每次前后移动后执行左右扫视。最新 O→B 日志中没有触发该分支，因此这些大距离不是成功原因。

建议：

1. 保留恢复框架和“发现路径立即停止”的逻辑。
2. 将大距离参数恢复为更保守的短距离，或者在路线验证阶段设置为空以禁用。
3. 在狭窄过道中不要使用接近 2 m 的开环倒车恢复，避免碰撞或离开安全走廊。
4. 正式航向恢复 `35,-70,105,-140°` 同样未在 O→B 中触发，可以默认保留但不视为核心修改。

## 8. 对 O→B 主效果影响很小、可以直接清理或按需求撤回的修改

| 修改 | 对 O→B 的影响 | 建议 |
|---|---|---|
| `MPC.cpython-*.pyc` 二进制缓存变化 | 无 | 直接撤回，不应提交 |
| `putn_mpc/scripts/controller.py` 手动键盘角速度上限改为 ±2 | 自动测试关闭本地控制器，不生效 | 可撤回；仅保留作手动底盘测试也可以 |
| `fusion_simulation.launch` 默认 LeSTA 权重、风险阈值变化 | 当前自动预热入口不依赖这些默认值 | 建议恢复原默认值，用启动参数显式指定实验配置 |
| `fusion_simulation.launch` 默认场景改为 `map1_wide` | 不影响专用自动测试 launch | 可恢复，避免改变原手动测试行为 |
| 默认移除 RGB camera extras | 对激光雷达导航非核心，只影响负载和相机话题 | 需要相机时可恢复 |
| CSV/JSON 汇总、P90、规划延迟和恢复时间统计 | 不改变机器人决策 | 不影响 O→B，但满足自动化评价目标，建议保留 |
| 双向测试和 `warmup_once` | 不影响单次 O→B 预热 | 后续正式评测需要，建议保留 |
| B→C→D→A→O 路线 | 对已完成的 O→B 无贡献 | 若目标仍是全地图预热必须保留；若测试范围永久缩为 O→B 才可删除 |
| `map1_wide` 的 ±X、-Y 平台扩展 | O→B 基本位于原地图内部 | 对 O→B 可撤回；对 B→C→D→A 的宽通道路线必须保留 |
| `goal_hold_s` 和新增评价字段 | 不影响预热路径跟随 | 建议保留，防止瞬间进入容差区被误判成功 |

## 9. 推荐的最小保留集合

若目标是得到一个尽量精简、仍能稳定完成 O→B 的版本，建议至少保留：

1. Scout 轮胎横向摩擦、PID 和 Gazebo PID 命名空间修复。
2. 横向半轮距差速公式修复。
3. O→B 四段人工安全走廊。
4. 不超过 2 m 的预热点插值。
5. 稳定路径接管、空路径保护和滚动子路径识别。
6. 大航向误差原地转向及其滞回逻辑。
7. 自动测试独占 `/cmd_vel`，并保持 `launch_local_control=false`。
8. 无进展时先重新发布目标；见过有效路径后不执行开环前后恢复。

建议暂时保留但等待消融验证：

1. 启动 bootstrap。
2. 激光雷达盲区补丁。
3. 主动投影恢复和正式航向恢复框架。
4. `map1_wide.yaml` 的 sparsity 阈值。

可以优先撤回或清理：

1. Python `.pyc` 缓存变化。
2. 仅服务手动键盘测试的角速度上限修改。
3. 与专用自动测试无关的 `fusion_simulation.launch` 默认值变化。
4. 原 `map1.yaml`、`map2.yaml` 中未经过对照实验的 sparsity 阈值变化。
5. 仅在后续全地图路线中使用的地图扩展和 B→C→D→A→O 路线；前提是任务范围确认永久缩小为 O→B。

## 10. 推荐消融测试顺序

不要同时撤回多项修改。建议固定同一随机环境和初始位姿，每组至少运行 5 次：

| 组别 | 唯一变化 | 目的 |
|---|---|---|
| Baseline | 保持当前成功配置 | 建立成功率和耗时基线 |
| A | 关闭投影恢复和航向恢复 | 验证它们确实不是 O→B 必要条件 |
| B | 关闭盲区补丁 | 测量起点投影失败率和首路径延迟 |
| C | 关闭 bootstrap | 判断初始地图运动预热是否必要 |
| D | 原地转向最小角速度逐级降到 1.5/1.2/1.0 | 找到不打滑且能克服摩擦的最小值 |
| E | 仅切换 `map1_wide` sparsity 阈值 | 隔离规划参数影响 |
| F | 分别降低 PID 或提高横向摩擦 | 仅在已有稳定基线后确定底盘参数余量 |

每组至少记录：

- O→B 成功率；
- O→B 总耗时；
- 首条有效路径延迟；
- 起点投影失败次数；
- 无进展重新规划次数；
- 投影/航向恢复次数；
- 原地转向次数和累计时间；
- 实际路径长度和最大横向偏差；
- 碰撞、侧翻和越界次数；
- 命令轮速与实际轮速误差。

只有当某项修改撤回后成功率、P90 导航时间和安全指标均无明显退化，才应将其从正式版本删除。

## 11. 当前结论与限制

当前最可信的因果结论是：

```text
底盘可实际转向
+ O→B 安全路线短程化
+ 稳定滚动路径接管
+ 大航向误差先原地对正
= 本次 O→B 预热成功
```

前后投影恢复、正式航向恢复和 B→C→D→A 地图扩展均不是本次 O→B 成功的直接原因。

但当前仍只有一次明确的成功运行，尚不能证明：

- O→B 在不同随机规划结果下具有稳定成功率；
- 完整 O→B→C→D→A→O 预热能够完成；
- PID、摩擦参数和最小角速度各自的独立贡献；
- 盲区点云补丁是否显著降低起点投影失败率；
- `ratio_min/ratio_max` 的变化是否改善或损害了规划质量。

因此，近期不建议大规模回滚。应先清理明显无关的缓存和手动调试修改，再按照第 10 节执行单变量消融测试，最终形成“最小有效修改集”。
